B · Follow the tenant_id thread

Every tenant-owned table carries a tenant_id that points back to one row in tenants. That single column is what RLS filters on — so isolation works the same way on every table.

tenants.id
↓   is referenced by   ↓
feedback.tenant_ideach submission
memberships.tenant_ideach staff link
feedback_notes.tenant_ideach note
💡 Why give feedback_notes its own tenant_id when it could find the tenant through feedback_id? Because then RLS can filter notes directly — no join needed — and the rule is identical on every table: tenant_id = me. Storing a value you could technically derive, to keep things simple/fast, is called denormalization. Here it's a deliberate choice in service of the isolation guarantee.

C · The one oddball — users is global

Every other table is owned by exactly one tenant. users isn't — it's a login identity that could (in theory) belong to more than one company. So it gets special handling instead of a tenant_id.

Why it can't just have RLS like the others: when you log in, we only have your email + password — we don't know your tenant yet. We have to find your users row first, then look up your memberships to learn which tenant you're in. So that one lookup can't be tenant-filtered.
How we keep it safe anyway:
1. Only the pulsepoint_app role can read users at all (the public ingest role can't touch it).
2. The only un-tenant-scoped query is "find user by email, to log in."
3. The dashboard never lists users directly. "Your team" is a query over memberships (which is RLS'd) joined to users — so you only ever see people who belong to your tenant.

D · The stats panel — no new table needed

Remember the dashboard stats strip we added? It needs zero new tables. It's just summary questions asked of the feedback table.

Queries like COUNT(*) … GROUP BY status or AVG(rating) run through the same RLS filter. So "12 open this week" automatically means "12 open for your tenant this week" — the isolation protects your totals exactly like it protects your row list. One less thing to get wrong.

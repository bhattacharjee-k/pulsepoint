PulsePoint — Test Guide

The 17 contract tests Codex must pass · maps each test to the guarantee it proves

How to read this

A test is just an automated sentence: "given a situation, when something happens, then this must be true." If reality disagrees, the test fails — loudly. Here's the vocabulary:

Unit test — checks one small piece of logic in isolation (e.g. "does the validator reject a bad email?"). Fast, no database.
Integration test — checks several pieces working together against a real test Postgres. The RLS guarantee can't be faked with mocks — it must hit a real database with the real roles + policies.
Given → When → Then — the shape of each test below: the setup, the action, and what must be true after.
Tool — Vitest runs them. HTTP tests use Fastify's inject() (no live server needed). DB tests connect to a throwaway test database.
💡 These are the contract — a floor, not a ceiling. Codex must make all 17 pass. In Stage 4, Claude runs a separate, adversarial security set that Codex never sees — so passing these isn't enough; the behavior has to be genuinely correct.

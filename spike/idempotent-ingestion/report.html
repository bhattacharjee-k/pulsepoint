1 · Correctness under a retry storm — graceful vs cliff

As clients retry more aggressively (x-axis), the naive count climbs linearly away from truth — a billing cliff. The idempotent line sits exactly on truth no matter how hard clients retry — graceful. This is the whole point: correctness is independent of delivery count.

Throughput rises, then saturates as the single server maxes out; past the knee, extra concurrency buys no throughput and only grows latency — a graceful degradation (queueing), not a crash. In production this is the signal to add ingest nodes (the design's ~10-node fleet). Note: server and load generator share one machine here, so absolute numbers are conservative; the shape is what matters.
